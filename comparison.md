## Detailed Analysis by Scanner Tier

### Tier 1: Out-of-the-Box `codex-security` (4 Findings)
OpenAI's baseline `codex-security` CLI performed a single-pass static trace and reported the 4 most prominent classic web vulnerability archetypes:
1. `[1]` **Arbitrary File Read**: `catch_all` route passing unsanitized paths to `send_file`.
2. `[2]` **Stored XSS**: User `name` and `bio` rendered without escaping in `directory.jinja2`.
3. `[3]` **Hardcoded Session Signing Key**: Static `SECRET_KEY` in `config.py` enabling cookie forgery.
4. `[4]` **SSRF**: Unvalidated `requests.get()` in `download_picture` fetching internal/attacker-selected URLs.

**What `codex-security` missed or combined**:
- *Reflected XSS* was not given a finding; it was only mentioned in the remediation/test suggestions for Stored XSS.
- *Unbounded Picture Download (DoS)* was described inside the SSRF root-cause narrative rather than flagged as an independent resource exhaustion finding.
- *Authentication, Business Logic, and Session Security* (Signup fail-open bypass, CSRF, account enumeration, missing rate limits, salt reuse, cookie flags) were entirely absent from its reportable findings.

---

### Tier 2: Custom BALLS on Codex Quick (9 Findings)
Running the BALLS multi-agent framework in Quick mode with Codex expanded the baseline to 9 findings by actively probing:
- Reflected XSS in `signin.jinja2` (`BALLS-004`).
- Signup partial-state failure bypass leaving `limited=None` (`BALLS-006`).
- Dedicated Unbounded Picture Download DoS (`BALLS-007`).
- Account Enumeration via error strings and timing (`BALLS-008`).
- Missing Sign-In attempt throttling (`BALLS-009`).

---

### Tier 3: Custom BALLS on Codex Full (13 Findings)
The full multi-agent scan on Codex added coverage for secondary and infrastructure risks:
- Shared static password salt `BCRYPT_SALT` across all users (`BALLS-009`).
- Pre-authentication full directory table load DoS (`BALLS-010`).
- Login CSRF (`BALLS-011`) and Forced Signout CSRF (`BALLS-013`).

---

### Tier 4: Custom BALLS on Google Antigravity (22 Findings)
Antigravity combined full CodeGraph call-graph indexing with 22 dedicated Pro verifiers across all 27 coverage units, promoting 9 additional confirmed vulnerabilities that all other tools missed or left in scope/evidence notes:
1. **Plaintext Credential Logging (`BALLS-013`)**: Verified `@app.after_request` unconditionally logs submitted passwords when running under default `DEBUG=True`.
2. **Password Policy Deficiencies (`BALLS-014`)**: Discovered ASCII decode crash (`UnicodeEncodeError` DoS) on special characters and silent 72-byte Bcrypt truncation.
3. **Missing Session Security Attributes (`BALLS-015`)**: Validated absence of `SameSite` and `Secure` cookie attributes, plus client-only logout without server revocation.
4. **Outdated Dependencies & CVEs (`BALLS-017`)**: Identified reachable `requests` redirect credential exposure (CVE-2018-18074) and unpinned lockfile risk.
5. **Internal API Injection (`BALLS-018`)**: Traced string concatenation into `LOOKUP` employee URL enabling path/query injection.
6. **Insufficient Audit Logging (`BALLS-019`)**: Flagged complete lack of audit trails for failed logins and security lifecycle events.
7. **Missing Security Response Headers (`BALLS-020`)**: Flagged absence of `X-Frame-Options`, `X-Content-Type-Options: nosniff`, and cache controls.
8. **Subresource Integrity (`BALLS-021`)**: Flagged unpinned HTTP CDN inclusion of jQuery in `base.jinja2` without integrity hashes.
9. **Active Default Debug Flag (`BALLS-022`)**: Flagged `BaseConfig.DEBUG = True` enabling Werkzeug interactive traceback exposure on unhandled exceptions.
